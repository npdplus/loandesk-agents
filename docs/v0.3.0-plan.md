# v0.3.0 plan — Multi-agent and lifecycle

**Goal:** a Front Desk agent hands work to specialist agents (one of them a Microsoft Foundry agent), a custom
prompt runs on a Foundry catalog model, and the solution moves from `LoanDesk-Dev` to a test environment
through a pipeline.

Work through the steps in order. Each step ends with something you can check. Tick the box when it is done.

## Constraints

- **The maker's Copilot Studio trial ends around 3 December 2026** (decision D7); it can be extended once
  by 30 days. Steps 1 to 7 need Copilot Studio, so they come first. Step 8 (study notes) can run any time.
- **The trial cannot publish.** That blocks three skill lines: channels, the identity of a published agent,
  and connecting an existing Copilot Studio agent (a connected agent must be published). Decision D15 in
  step 0 settles whether to pay for publishing or to cover these lines as design notes.
- **Preview features.** Connecting a Foundry agent is preview, works only with standard-harness agents, and
  needs the Foundry agent's Activity endpoint enabled through the REST API or the Python SDK.
- **Cost.** A Foundry model deployment is billed per token; a managed test environment and its agent flow
  runs use pay-as-you-go meters. Keep the USD 10 budget alert on `rg-loandesk-dev` and check credits after
  each step.

      a pipeline target), or export/import by hand. Recommended: managed environment, deleted after the
      release if it costs more than expected
- [ ] **D17 Front Desk:** turn the Apply Agent into the Front Desk (it already has the topics, tools and
